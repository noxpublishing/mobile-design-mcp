# Mobile design quality

Use during an authorized design implementation or for a requested audit of an
existing screen/flow. Read the relevant checks in
[mobile quality](../../docs/mobile-quality.md). Reuse the actual app direction,
theme and components; do not invent a house style, universal font count or visual
ban list. Resolve only missing facts that materially change the current task.

Inspect the primary task, realistic content, normal/enlarged text, meaningful
states and the actual platform/stack. During implementation correct concrete
problems inside the agreed scope. For an audit report evidence/state, user impact,
severity, correction and rerun; apply fixes within the user's existing authority.

Ask whether hierarchy exposes the task, repeated roles share spacing/type, actions
have understandable outcomes, and decoration/motion serve an identifiable purpose.
Check touch/semantic access, keyboard and back behavior, safe areas, recovery,
interruption and reduced motion where relevant. Label missing runtime evidence
separately from a visible defect. Do not classify AI authorship or score taste.

Use the existing specialist profiles and
[shared review contract](../../docs/workflow.md). Keep app source authoritative,
retain intentional differences and invalidate only affected old evidence. Report
what changed and what was actually verified; attractive captures alone do not
establish task completion or measured performance.
